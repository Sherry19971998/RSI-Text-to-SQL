# “生成→反馈→迭代修改”类方法：通用领域与 Text-to-SQL

检索与核对日期：2026-10-31。所有条目的标题、第一作者、提交日期和发表信息都来自 arXiv API。会议名只在 arXiv 的 comment 或 journal_ref 字段写明时才列出。一句话说明根据摘要整理。

检索方式：arXiv 标题与摘要检索，关键词为 text-to-SQL 加上 correction / refine / feedback / debug / repair / multi-turn / reinforcement / agent。按标题命中约 130 篇，下表只列代表作。这不是系统性综述，所以不能据此断言某个方向“无人研究”。

## 结论

- **Text-to-SQL 里这类工作很多。** 从 2020 年用自然语言反馈改 SQL（SPLASH），到 2023 年的提示式自我修正（DIN-SQL、Self-Debug），再到 2025–2026 年用执行反馈做多轮强化学习（MTIR-SQL、SQL-Trail、TRUST-SQL 等），每年都有新论文。
- **反馈主要来自执行器。** 2026 年一项 17 种配置的受控比较发现，在常见模块里，只有“执行反馈修正”在所有底座模型上都有收益，而且成本低（2608.28432）。
- **Huang 等人指出的问题在 SQL 里同样存在。** 多篇论文报告，自我修正常把原本正确的 SQL 改错（SQLCritic、ErrorLLM、MapleDoctor）。ErrorLLM 还指出，现代大模型很少写出会报错的 SQL，单靠报错信息触发的 self-debugging 越来越没用。
- **和我们最相关的新动向：**
  - 用执行反馈训练多轮修正的强化学习，2025 年下半年起集中出现；
  - ReToolSQL 发现，监督微调能扩大覆盖率（pass@k），强化微调则把它转成单次准确率；
  - MIRA、Memo-SQL 和人类反馈持续学习这三篇，把修正经验存进记忆库复用，与“结晶化”论文思路相近。
