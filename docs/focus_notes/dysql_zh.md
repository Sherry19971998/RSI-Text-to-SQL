# DySQL-Bench（Sun 等，arXiv 2510.26495）

第一作者：Linzhuang Sun（中国科学院大学）；合作单位：北京大学、清华大学；通讯作者 Wentao Zhang、Bin Cui（北大）。

**一句话：** 含 1,072 个多轮对话式数据库任务的基准，模拟用户的需求逐轮变化；GPT-4o 总体仅 58.34%，Pass^5 仅 23.81%。

**如何构建：**
- 数据：BIRD 与 Spider 2 的 13 个 SQLite 库；按外键把每条记录展开成 JSON 树，再由 GPT-4.1 生成用户指令和标准 SQL 动作。
- 覆盖完整 CRUD：UPDATE 49.64%、SELECT 28.93%、DELETE 10.80%、INSERT 10.63%；分 Short（少于 3 个动作）和 Long（3 个及以上）。
- 质控：DeepSeek-R1 与 Qwen3-235B 双模型校验，把缺失参数补回指令，标准 SQL 必须能执行，最后由 10 位专家逐条检查。
- 交互：Qwen2.5-72B-Instruct 扮演用户，信息逐轮给出；被测模型可以回复、执行 SQL 或推理；用户输出 ###STOP### 或满 30 轮即结束。
- 评测：去掉时间戳列后对最终数据库状态做哈希，与执行标准动作后的状态一致才算成功。

**关键结果：**

| 项目 | 数值 |
|---|---|
| GPT-4o 总体（摘要） | Pass^1 58.34%，Pass^5 23.81% |
| Qwen2.5-72B-Instruct，retail world | Pass^1 90.32 → Pass^5 74.19 |
| Gemini-2.5-Flash，retail | Pass^1 0.98 |
| 幻觉率（模型自己编造 SQL 结果） | DeepSeek-V3 44.28%，OmniSQL-32B 26.15%，GPT-4o 0.09% |
| Few-shot（CA/EN/PA 平均，0→3-shot） | GPT-4o 62.60→64.68；Qwen2.5-72B 63.39→65.52 |

**关键公式：**
- Pass^k = E_task[ C(c,k) / C(n,k) ]（n 次运行中 c 次成功）：随机取 k 次运行全部成功的概率，用来衡量稳定性。
- 成功 = [hash(S₂) = hash(S₃)]，其中 S₂ 是模型动作执行后的状态，S₃ = execute(A_g | S₁) 是标准动作执行后的状态。

**局限：**
- 只用一个 LLM（Qwen2.5-72B）模拟用户，分数受它的行为影响；任务围绕单条记录生成，偏向 UPDATE 类事务，不是分析型查询。
- 表格只给出分领域分数，总体数字只出现在摘要里；任务数也对不上（561 + 501 = 1,062，不是 1,072）。

**对本项目：**
- 只能部分作为迁移测试：它和我们一样用到 BIRD 数据库和执行反馈，但它是带模拟用户的对话式任务，以写操作为主，评的是最终数据库状态而不是 BIRD EX。
- 要用它，需要：给 7–8B 模型做对话/工具调用格式；同时部署一个 72B 的用户模拟器（GPU 成本高，而我们没有本地 GPU）；每题多次运行以计算 Pass^k；支持 INSERT/UPDATE/DELETE（我们的训练数据只有 SELECT）。
- Pass^k 很适合检验我们的覆盖率问题：自训练让模型“变尖锐”，预计 Pass^k（稳定性）会更好，而 frontier 应保留更多覆盖。可以对 θ0（BIRD EX 53.06）和 frontier（59.34）分别报告 Pass^1 和 Pass^5 来验证。
