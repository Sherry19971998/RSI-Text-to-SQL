# CSC-SQL (arXiv 2505.13271)

**一句话：** 取多数投票前两组 SQL，交给 GRPO 训练的修正模型合并改写；BIRD 私有测试集 EX 71.72%（7B）、73.67%（32B）。

**方法：**
- 采样 N 条 SQL（T=0.8），执行后按结果分组。
- 前两组一致就直接输出；否则把两条 SQL 和结果放入修正提示。
- 修正模型再采样 8 条，再投票。
- 生成和修正模型都在 BIRD train 上用 GRPO 训练。

**关键结果：**（EX %，默认 BIRD dev）

| 设置 | SC | CSC |
|---|---|---|
| Qwen2.5-Coder-7B 原始, n=8 | 62.18 | 64.28 |
| Qwen2.5-Coder-7B GRPO, n=8 | 64.95 | 66.96 |
| Qwen2.5-Coder-7B GRPO, n=64 | 66.15 | 69.19 |
| 7B，私有测试 | – | 71.72 |
| 32B，私有测试 | – | 73.67 |

**关键公式：**
- R = R_EX + 0.1 · R_Format：执行正确得 1，格式正确再加 0.1。
- major_top2_pass@k：只在票数最多的两组里算 pass@k；第一名错时正确答案常在前两组。

**局限：**
- 推理开销高于普通 SC；采样多样性低时提升小。
- 只测 BIRD 和 Spider；没有多轮训练，也没分析覆盖率。

**对我们项目：**
- 同基座、同温度、同数据集：原始 7B SC n=8 dev 62.18，我们 θ0 为 53.06（提示不同）。
- n 越大 GRPO 增益越小（SC：n=8 +2.77，n=64 +1.70），与我们的 sharpening 发现一致。
- top-2 合并修正可作 frontier 模型的低成本推理增强，或修复轨迹来源。
